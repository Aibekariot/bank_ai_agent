# Контракт ассистента с приложением банка

Здесь описано всё, что нужно приложению, чтобы встроить ассистента: запрос к серверу,
ответ и действия. Каталог действий: [actions.json](actions.json). Его читают и сервер,
и тесты приложения, поэтому новое действие начинается со строки в каталоге.

## Запрос

`POST /v1/chat` (старый адрес `/chat` работает так же)

```json
{
  "messages": [
    {"role": "user", "text": "Переведи 500 сом на 0555 123 456"}
  ],
  "session_id": "a1b2c3"
}
```

- `messages`: диалог, последнее сообщение от `user`, до 2000 символов. Сервер берёт последние 20 сообщений.
- `session_id`: необязательно, идентификатор диалога. Пока не хранится на сервере.
- Заголовок `Authorization: Bearer <токен приложения>`. Пока не проверяется (в демо токен вымышленный); проверка появится вместе с личными данными.

## Ответ

```json
{
  "reply": "Форма перевода готова. Проверьте данные и подтвердите перевод в приложении.",
  "actions": [
    {
      "name": "open_transfer_by_phone",
      "label": "Перевод по номеру телефона",
      "params": {"phone": "+996555123456", "amount": 500, "currency": "KGS"}
    }
  ]
}
```

- `reply`: текст ответа (Markdown).
- `actions`: до 3 действий, может быть пустым. Приложение показывает их кнопками под ответом, по нажатию выполняет.

Ошибки приходят с понятным текстом в `detail`: 400 (неверная история), 422 (неверный формат запроса), 503 (модель перегружена), 500 (прочее).

## Правила для действий

1. Ассистент только предлагает. Действие выполняется, когда клиент нажимает кнопку.
2. `kind: navigate` в каталоге: приложение открывает свой экран с параметрами.
3. `kind: operation`: приложение открывает свой экран операции с заполненными полями. Провести операцию можно только после обычного подтверждения клиента в приложении (PIN, биометрия, OTP). Автоматически операция не проводится никогда.
4. Сервер проверяет каждое действие по каталогу. Приложение тоже проверяет: неизвестное действие не показывается, неверный параметр не подставляется.
5. Подписи `label` на русском, это запасной вариант. Приложение может показывать свои подписи по `name`.

## Действия (версия каталога 1)

| name | kind | Параметры | Что делает приложение |
| --- | --- | --- | --- |
| `open_exchange_rates` | navigate | `currency` (USD, EUR...) | Экран курсов валют |
| `open_locations` | navigate | `city`, `kind` (atm, branch, savings_cash, mobile_cash) | Список банкоматов и отделений |
| `open_card_product` | navigate | `slug` (обязательно), `title` | Страница карты |
| `open_pin_change` | navigate | нет | Смена PIN-кода карты |
| `open_transfer_by_phone` | operation | `phone` (+996XXXXXXXXX), `amount`, `currency` (KGS) | Форма перевода, затем подтверждение клиентом |

Добавить действие: строка в `actions.json` (с `example`), подсказка в инструменте сервера, обработчик в приложении. Изменить или удалить существующее: новая версия каталога.

## Только для демо

`/demo-bank/v1/*` (курсы, точки, карты) имитирует API банка для демо-приложения из этого репозитория. Настоящее приложение берёт эти данные из своих систем.
