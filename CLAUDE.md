## Что это

Публичный информационный ИИ-чат для клиентов Eldik Bank (Кыргызстан), физические лица.
Стажёрский проект: тимлид ставит задачи и проверяет результат. Владелец кода: Aibek.
Репозиторий: https://github.com/Aibekariot/bank_ai_agent

Стек: FastAPI-бэкенд (`backend/`), LLM через OpenRouter
(`nvidia/nemotron-3-super-120b-a12b:free`) или Gemini (`LLM_PROVIDER`). Flutter: модуль чата
`packages/eldik_assistant` (его подключит приложение банка) и демо-банк в `lib/` (тестовое
приложение-хозяин). Контракт ассистента с приложением: `contract/` (README и каталог действий).
Внимание: если `LLM_PROVIDER` не задан, `llm/factory.py` выбирает `gemini`. Рабочий режим сейчас `openrouter` из `.env`.

## Главные правила (нарушать нельзя)

1. Агент НЕ выдумывает ставки, комиссии, сроки и условия. Нет в данных значит "нет сведений" и контакт-центр 9111.
2. `null` в данных означает "не указано", а не "бесплатно" и не "нет".
3. Все расчёты (кредит, вклад) делает код, не модель.
4. Доступа к личным счетам и персональным данным клиента у агента нет.
5. Если два источника расходятся, называем оба и не складываем и не пересчитываем сами.
6. Сроки акций и программ сравниваются с сегодняшней датой при КАЖДОМ ответе (`tools._validity`). Истёкшее не называть действующим.
7. Изменения небольшие и безопасные. К правке прилагать краткое объяснение и полный файл, если файл заменяется целиком.
8. Секреты (`backend/.env`) не коммитить. Файл в `.gitignore`.

## Стадии

- Demo (сейчас): справочный агент по физлицам, русский язык, данные с сайта, калькуляторы, список банкоматов и отделений.
- Pilot: официальные данные от банка, кыргызский, бизнес-клиенты (вероятность около 80%), логирование, оценка качества.
- Production: интеграция с банком, безопасность, нагрузка.

Отложено осознанно: база данных (данные лежат в JSON в памяти), выбор лучшей модели и расчёт железа и стоимости (задача тимлиду), качество кыргызского языка (ограничение бесплатной модели).

## Как устроено

```
Демо-банк (lib/) -> модуль чата (packages/eldik_assistant) -> POST /v1/chat (история, session_id, токен)
   -> agent.run_chat: scope_guard (до LLM) -> LLM (llm/factory) -> цикл инструментов (до 3 раундов)
   инструменты (tools.py) -> knowledge.py (поиск по backend/knowledge/*.json)
   подсказки действий из инструментов -> actions.validate по contract/actions.json
<- {reply, actions[]} -> кнопки под ответом -> DemoActionHandler открывает экран приложения
```

Действия (главный принцип: ассистент предлагает, приложение выполняет, деньги двигает только клиент):
- Каталог `contract/actions.json`: 5 действий (`open_exchange_rates`, `open_locations`, `open_card_product`, `open_pin_change`, `open_transfer_by_phone`), у каждого параметры и `example`. Его читают сервер и тесты приложения.
- Инструменты кладут подсказки под ключ `_app_actions` (курсы, найденные точки, 1-3 найденные карты, инструкция PIN, черновик перевода). Агент забирает их (`actions.take_hints`), проверяет по каталогу, модели отдаёт только подписи кнопок (`app_buttons`). Не больше 3 кнопок.
- `prepare_transfer`: черновик перевода по номеру (только KGS, номер нормализуется в +996XXXXXXXXX). Перевод НЕ выполняется: приложение открывает форму, клиент подтверждает PIN-кодом. Раздел 17 промпта запрещает писать, что деньги отправлены.
- Новое действие: строка в `actions.json` (с `example`), подсказка в инструменте, обработчик в `DemoActionHandler.screenFor`. Тесты с обеих сторон проверяют, что примеры из каталога работают.

Ключевые файлы `backend/`:
- `agent.py`: системный промпт (разделы 1-17), цикл инструментов, сбор действий, `ChatResult(reply, actions)`, логи `[TIMING]`, `[TOOL]`, `[ACTIONS]`, `[LLM]`, `[CHAT] total`.
- `actions.py`: проверка действий по каталогу, `normalize_kg_phone`.
- `demo_bank_api.py`: `/demo-bank/v1/rates|locations|cards|cards/{slug}` для экранов демо-банка. Это имитация API банка, к агенту не относится.
- `scope_guard.py`: фильтр тем до LLM. Порядок: пусто, инъекция, жёсткие посторонние темы, банковские слова, вежливость и мета-вопросы, мягкие посторонние темы, уточнение. Есть слова на ru, ky, en, опечатки, разбивку букв пробелами.
- `language.py`: определение языка (ru/ky/en), подсказка модели, тексты отказов. Кыргызский список слов и отказ нужно проверить носителем.
- `tools.py`: инструменты `search_bank_products`, `search_knowledge`, `list_card_products`, `list_credit_products`, `list_deposit_products`, `get_tariff_documents`, `find_locations`, `get_bank_contacts`, `get_exchange_rate` (живой запрос; build id сайта берётся со страницы и обновляется при 404; 16.10 сайт снова пересобрали, подхватилось само), `prepare_transfer`, `calculate_loan_payment`, `calculate_deposit_income`.
- `knowledge.py`: загрузка и лексический поиск. `locations.json` отдельный набор (`items`, не `documents`).
- `main.py`: `/health`, `/v1/chat` (и старый `/chat`): ответ `{reply, actions}`, принимает `session_id` и заголовок `Authorization` (токен пока не проверяется, только отметка `[AUTH]` в логе). Ошибки клиенту безопасные (503 для 429, 500 общий). `prepare_history` ограничивает историю от клиента: роли только `user`/`model`, последним должно быть сообщение `user` (до 2000 символов), модели уходят последние 20 сообщений, старые обрезаются до 3000 символов.
- `llm/openrouter.py`: один повтор через 4 с при 429. Провайдер создаётся на каждый запрос и закрывается (`close()`) в `agent.run_chat`.
- `llm/gemini.py`: запасной провайдер на устаревшем SDK `google-generativeai`. Перевести на `google-genai` при сравнении моделей.
- `dev_log.py`: `DEV_LOG=1` пишет `backend/logs/dialogs.txt`. По умолчанию выключено, на реальных данных клиентов не включать.

Flutter:
- `packages/eldik_assistant`: модуль чата для встраивания. `AssistantConfig` (адрес, токен, session_id), `AssistantChatScreen`, `AssistantApi` (`/v1/chat`), `AssistantAction` и интерфейс `AssistantActionHandler` (приложение-хозяин выполняет действия; без обработчика кнопок нет; показываются только `supportedActions`). Сообщения об ошибках связи (`isError`) и приветствие на сервер не уходят. Текст ошибки берётся из `detail`.
- `lib/demo_bank`: демо-банк. Вход тестового клиента (PIN 1234), главный экран со счетами и картами, экраны курсов, точек, карт банка, смены PIN, перевода по номеру (форма, подтверждение PIN, результат; плашка «заполнено ассистентом»). `FakeBankStore`: вымышленные счета и карты в памяти. `HttpDemoBankApi`: данные с `/demo-bank/v1`. `DemoActionHandler`: действие -> экран, сам перепроверяет параметры. Метка «ДЕМО» на каждом экране, все данные вымышленные, APK не распространять за пределы команды.
- Адрес сервера: `flutter run --dart-define=API_BASE_URL=http://<IP>:8000` (по умолчанию локальный IP в `lib/demo_bank/config.dart`; для эмулятора Android `http://10.0.2.2:8000`).
- В основном `AndroidManifest.xml` есть `INTERNET` и `usesCleartextTraffic` (демо-сервер по http). Когда сервер перейдёт на https, `usesCleartextTraffic` убрать. Подпись приложения: «Демо-банк».

Переменные окружения (`backend/.env`, значения не хранить в репозитории):
`LLM_PROVIDER`, `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `DEV_LOG`, `KNOWLEDGE_DIR`, `ELDIK_BUILD_ID` (необязательно).

## Данные: откуда и как собираются

Сырые файлы лежат в `jisonki_eldika/`. Скрипт `backend/scripts/build_knowledge.py` превращает их в `backend/knowledge/*.json` (результат тоже в Git).

Источники, которые понимает скрипт, по порядку важности. Отмечено, что реально лежит в `jisonki_eldika/` на 2026-10-15:
1. `api_cards/<slug>.json` ответ `/api/cards/<slug>` (стабильный адрес). ПАПКИ ПОКА НЕТ.
2. `_next/data/<buildId>/...` файлы Next.js (адрес ломается при каждом обновлении сайта, buildId меняется). ЕСТЬ: это папки `N1_*`, `depozits_eldika` и другие.
3. `manual_cards/<slug>.json` данные, внесённые вручную из текста страницы (World Elite, Visa Infinite). Помечены датой и списком расхождений. ЕСТЬ.
4. `api_branches/region_N.json` ответы `/api/branches?region=N`, по одному файлу на область. ЕСТЬ все регионы 2-9 (120 точек, 2026-10-15). Все они совпали с точками, уже собранными со страниц сайта: база подтверждена, новых точек нет. Банкоматов в этих ответах нет.
5. `i18n/ky|en/payment-cards.json` версии списка карт на других языках. Используются ТОЛЬКО для сверки сумм: если ru и ky/en расходятся, поле обнуляется. ЕСТЬ `i18n/ky/payment-cards.json` (только `pageProps.data` страницы /ky/payment-cards) и `i18n/en/payment-cards.json` (страница целиком), оба 2026-10-15.

Уже известные спорные поля дополнительно перечислены в `KNOWN_DISPUTED_FEES` в `build_knowledge.py` и обнуляются всегда, даже без файлов i18n (сейчас: `elkart-beskontakt.issuance`). Сверка сейчас сама находит это расхождение (ru 350 сом, ky и en 100 сом), остальные 9 карт совпадают.

Страница `/ky/cards/change-pin-code` проверена 2026-10-15: те же 70 банкоматов и 35 точек Бишкека, что в ru-версии, только названия на кыргызском. Строки PIN на ky уже есть в ru-файле. Отдельно не сохранена.

Разделы базы: cards, credits, deposits, overdraft, transfers, accounts, islamic, salary_project, mobile_banking, instructions (смена PIN), card_privileges (подробности привилегий премиальных карт), tariffs, legal (в поиск не попадает), locations.

Правила данных:
- Поле `detail_level`: `detail` или `list` (только короткие данные из списка). Для `list` в ответе пометка, что условия неполные.
- Не хранится режим работы точек: `status`, `is_open` в сырых данных это снимок и противоречат друг другу.
- Строки интерфейса `_nextI18Next` не мусор: там инструкция по смене PIN (ru и ky) и словарь ru-ky-en (около 1080 фраз). Словарь пока не использован.
- Отчёт о сборке (пробелы, расхождения, пропущенные файлы) пишется в `backend/knowledge/_manifest.json`, поле `gaps`.

Сборка и проверка (Windows, из папки `backend`):
```
.venv\Scripts\activate
set PYTHONUTF8=1
python scripts\build_knowledge.py --data-date ГГГГ-ММ-ДД
python tests\test_build_knowledge.py
python tests\test_tools.py
python tests\test_scope_guard.py
python tests\test_main.py
python tests\test_actions.py
```
Flutter (из корня репозитория и из `packages/eldik_assistant`): `flutter analyze` и `flutter test`.
Проверка с живым сервером (по желанию, тратит запросы к модели):
`flutter test test/live_server_test.dart --dart-define=LIVE_API=http://127.0.0.1:8000`.

`PYTHONUTF8=1` обязателен: без него консоль Windows (cp1251) падает с `UnicodeEncodeError` на кыргызских буквах.
`--data-date` указывать как реальную дату скачивания данных. После сборки закоммитить `backend/knowledge`.

Запуск сервера: `uvicorn main:app --reload --host 0.0.0.0 --port 8000` (из `backend`). Адрес сервера для приложения задаётся `--dart-define=API_BASE_URL` (см. Flutter выше).

## Как работать с этим репозиторием (для Claude)

- Сначала прочитать этот файл и `backend/tests/TEST_QUESTIONS.md`.
- Перед правкой промпта или данных проверить влияние на тестовые вопросы. После правок запускать пять наборов тестов сервера (с `PYTHONUTF8=1`), а после правок Flutter `flutter analyze` и `flutter test` в корне и в `packages/eldik_assistant`.
- Ассистент никогда не проводит операции сам: только черновик и кнопка, подтверждение в приложении. Не добавлять действия в обход каталога `contract/actions.json`.
- Новые факты вносить в сырые данные и пересобирать базу, а не править `backend/knowledge/*.json` вручную.
- Если пользователь просит "статус проекта", обновить раздел "Статус" выше и показать, что изменилось.
- Не предлагать сайт или чужие ресурсы для обхода запретов: `robots.txt` сайта запрещает `/api/` для автоматических запросов, данные пользователь приносит сам из браузера.
