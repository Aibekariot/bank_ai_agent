# Eldik Bank AI Agent: контекст проекта для Claude

Этот файл читает Claude Code при старте. Обновляйте его, когда меняются решения или статус.
Последнее обновление: 2026-10-15.

## Что это

Публичный информационный ИИ-чат для клиентов Eldik Bank (Кыргызстан), физические лица.
Стажёрский проект: тимлид ставит задачи и проверяет результат. Владелец кода: Aibek.
Репозиторий: https://github.com/Aibekariot/bank_ai_agent

Стек: Flutter-клиент (`lib/`), FastAPI-бэкенд (`backend/`), LLM через OpenRouter
(`nvidia/nemotron-3-super-120b-a12b:free`) или Gemini (`LLM_PROVIDER`).
Внимание: если `LLM_PROVIDER` не задан, `llm/factory.py` выбирает `gemini`. Рабочий режим сейчас `openrouter` из `.env`.

## Главные правила (нарушать нельзя)

1. Агент НЕ выдумывает ставки, комиссии, сроки и условия. Нет в данных значит "нет сведений" и контакт-центр 9111.
2. `null` в данных означает "не указано", а не "бесплатно" и не "нет".
3. Все расчёты (кредит, вклад) делает код, не модель.
4. Доступа к личным счетам и персональным данным клиента у агента нет.
5. Если два источника расходятся, называем оба и не складываем и не пересчитываем сами.
6. Сроки акций и программ сравниваются с сегодняшней датой при КАЖДОМ ответе (`tools._validity`). Истёкшее не называть действующим.
7. Изменения небольшие и безопасные. К правке прилагать краткое объяснение и полный файл, если файл заменяется целиком.
8. Секреты (`backend/.env`) не коммитить. Файл в `.gitignore`.

## Стадии

- Demo (сейчас): справочный агент по физлицам, русский язык, данные с сайта, калькуляторы, список банкоматов и отделений.
- Pilot: официальные данные от банка, кыргызский, бизнес-клиенты (вероятность около 80%), логирование, оценка качества.
- Production: интеграция с банком, безопасность, нагрузка.

Отложено осознанно: база данных (данные лежат в JSON в памяти), выбор лучшей модели и расчёт железа и стоимости (задача тимлиду), качество кыргызского языка (ограничение бесплатной модели).

## Как устроено

```
Flutter  ->  POST /chat (вся история)  ->  agent.run_chat
   scope_guard (до LLM)  ->  LLM (llm/factory)  ->  цикл инструментов (до 3 раундов)
   инструменты (tools.py)  ->  knowledge.py (поиск по backend/knowledge/*.json)
```

Ключевые файлы `backend/`:
- `agent.py`: системный промпт (разделы 1-16), цикл инструментов, логи `[TIMING]`, `[TOOL]`, `[LLM]`, `[CHAT] total`.
- `scope_guard.py`: фильтр тем до LLM. Порядок: пусто, инъекция, жёсткие посторонние темы, банковские слова, вежливость и мета-вопросы, мягкие посторонние темы, уточнение. Есть слова на ru, ky, en, опечатки, разбивку букв пробелами.
- `language.py`: определение языка (ru/ky/en), подсказка модели, тексты отказов. Кыргызский список слов и отказ нужно проверить носителем.
- `tools.py`: инструменты `search_bank_products`, `search_knowledge`, `list_card_products`, `list_credit_products`, `list_deposit_products`, `get_tariff_documents`, `find_locations`, `get_bank_contacts`, `get_exchange_rate` (живой запрос), `calculate_loan_payment`, `calculate_deposit_income`.
- `knowledge.py`: загрузка и лексический поиск. `locations.json` отдельный набор (`items`, не `documents`).
- `main.py`: `/health`, `/chat`. Ошибки клиенту безопасные (503 для 429, 500 общий).
- `llm/openrouter.py`: один повтор через 4 с при 429.
- `dev_log.py`: `DEV_LOG=1` пишет `backend/logs/dialogs.txt`. По умолчанию выключено, на реальных данных клиентов не включать.

Flutter (`lib/`): сообщения об ошибках связи помечаются `isError` и не отправляются на сервер в истории. Текст ошибки пользователю берётся из `detail` ответа сервера.

Переменные окружения (`backend/.env`, значения не хранить в репозитории):
`LLM_PROVIDER`, `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `DEV_LOG`, `KNOWLEDGE_DIR`.
(`DATABASE_URL` в `.env` остался от старого кода БД и не используется.)

## Данные: откуда и как собираются

Сырые файлы лежат в `jisonki_eldika/`. Скрипт `backend/scripts/build_knowledge.py` превращает их в `backend/knowledge/*.json` (результат тоже в Git).

Источники, которые понимает скрипт, по порядку важности. Отмечено, что реально лежит в `jisonki_eldika/` на 2026-10-15:
1. `api_cards/<slug>.json` ответ `/api/cards/<slug>` (стабильный адрес). ПАПКИ ПОКА НЕТ.
2. `_next/data/<buildId>/...` файлы Next.js (адрес ломается при каждом обновлении сайта, buildId меняется). ЕСТЬ: это папки `N1_*`, `depozits_eldika` и другие.
3. `manual_cards/<slug>.json` данные, внесённые вручную из текста страницы (World Elite, Visa Infinite). Помечены датой и списком расхождений. ЕСТЬ.
4. `api_branches/region_N.json` ответы `/api/branches?region=N`, по одному файлу на область (регионы 2-9). ЕСТЬ `region_2` (Баткенская, 9 точек) и `region_8` (Иссык-Кульская, 10 точек), 2026-10-15. Все эти точки уже были в базе со страницы зарплатного проекта, новых не добавилось. Остальных регионов (3-7, 9) ПОКА НЕТ. Сейчас 233 точки в `locations.json` собраны из файлов Next.js (страницы смены PIN, исламского окна, зарплатного проекта).
5. `i18n/ky|en/payment-cards.json` версии списка карт на других языках. Используются ТОЛЬКО для сверки сумм: если ru и ky/en расходятся, поле обнуляется. ЕСТЬ `i18n/ky/payment-cards.json` (только `pageProps.data` страницы /ky/payment-cards) и `i18n/en/payment-cards.json` (страница целиком), оба 2026-10-15.

Уже известные спорные поля дополнительно перечислены в `KNOWN_DISPUTED_FEES` в `build_knowledge.py` и обнуляются всегда, даже без файлов i18n (сейчас: `elkart-beskontakt.issuance`). Сверка сейчас сама находит это расхождение (ru 350 сом, ky и en 100 сом), остальные 9 карт совпадают.

Страница `/ky/cards/change-pin-code` проверена 2026-10-15: те же 70 банкоматов и 35 точек Бишкека, что в ru-версии, только названия на кыргызском. Строки PIN на ky уже есть в ru-файле. Отдельно не сохранена.

Разделы базы: cards, credits, deposits, overdraft, transfers, accounts, islamic, salary_project, mobile_banking, instructions (смена PIN), card_privileges (подробности привилегий премиальных карт), tariffs, legal (в поиск не попадает), locations.

Правила данных:
- Поле `detail_level`: `detail` или `list` (только короткие данные из списка). Для `list` в ответе пометка, что условия неполные.
- Не хранится режим работы точек: `status`, `is_open` в сырых данных это снимок и противоречат друг другу.
- Строки интерфейса `_nextI18Next` не мусор: там инструкция по смене PIN (ru и ky) и словарь ru-ky-en (около 1080 фраз). Словарь пока не использован.
- Отчёт о сборке (пробелы, расхождения, пропущенные файлы) пишется в `backend/knowledge/_manifest.json`, поле `gaps`.

Сборка и проверка (Windows, из папки `backend`):
```
.venv\Scripts\activate
set PYTHONUTF8=1
python scripts\build_knowledge.py --data-date ГГГГ-ММ-ДД
python tests\test_build_knowledge.py
python tests\test_tools.py
python tests\test_scope_guard.py
```
`PYTHONUTF8=1` обязателен: без него консоль Windows (cp1251) падает с `UnicodeEncodeError` на кыргызских буквах.
`--data-date` указывать как реальную дату скачивания данных. После сборки закоммитить `backend/knowledge`.

Запуск сервера: `uvicorn main:app --reload --host 0.0.0.0 --port 8000` (из `backend`). Адрес сервера для клиента задан в `lib/services/api_service.dart` (`baseUrl`, сейчас локальный IP).

## Как работать с этим репозиторием (для Claude)

- Сначала прочитать этот файл и `backend/tests/TEST_QUESTIONS.md`.
- Перед правкой промпта или данных проверить влияние на тестовые вопросы. После правок запускать три набора тестов (с `PYTHONUTF8=1`).
- Новые факты вносить в сырые данные и пересобирать базу, а не править `backend/knowledge/*.json` вручную.
- Если пользователь просит "статус проекта", обновить раздел "Статус" выше и показать, что изменилось.
- Не предлагать сайт или чужие ресурсы для обхода запретов: `robots.txt` сайта запрещает `/api/` для автоматических запросов, данные пользователь приносит сам из браузера.
